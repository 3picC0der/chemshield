# Aspen pH tables — file format (CHE → ISE)

**Owner of the format:** Hattan (ISE). **Owner of the data:** Abdulkarim (CHE).
This is the only thing the simulator needs from Aspen. Drop the files in this folder
and the simulator picks them up — no code changes.

## The contract

One CSV file per Aspen sensitivity run, **or** one combined CSV. Either works.
The loader concatenates every `*.csv` in this folder except files starting with `_`.

### Columns — exactly these four names, in any order, lower case

| Column | Units | Meaning |
|---|---|---|
| `case` | text | Which Aspen run this row came from: `T1`…`T6`. Free text, never parsed. |
| `temp_c` | °C | Temperature of the run (20, 25, 30, 35). |
| `excess_mmol` | mmol | Net strong-base excess in a **5.000 L** tank. **Negative = extra acid, positive = extra base.** |
| `ph` | — | Aspen's `PH` for the tank outlet stream at that excess. |

### Sign convention — please read this twice

`excess_mmol` is **base-positive**:

- Table T1 (adding 0.5 M HCl to the tank liquid) produces rows from `0` down to `−60`.
- Table T2 (adding 0.5 M NaOH to the tank liquid) produces rows from `0` up to `+60`.
- `0` is the tank liquid as prepared (see below), **not** pH 7.

### The liquid

The tank holds **5.000 L distilled water + 0.420 g NaHCO3** (5.0 mmol, 1 mmol/L), chosen by
the team on 29 Sep. Both Aspen runs start from that liquid, not from pure water. With it,
`excess_mmol = 0` is about pH 8.30.
- pH must therefore **increase** as `excess_mmol` increases. The loader checks this and
  refuses the file if it does not — that check is there to catch a flipped sign.

### Basis

Every row is for a **5.000 L** tank. The simulator corrects for the extra volume added by
doses itself, by looking the table up at `excess_mmol × 5.0 / volume_L`. Do not pre-correct.

### Point spacing

Use the spacing from the Simulation and Dataset Guide (Part 1, A3), with the 0.05 mmol
steps carried on to 8 mmol for the NaHCO3 liquid:

- `0` → `0.2` mmol in steps of **0.002**
- `0.2` → `8` mmol in steps of 0.05  *(the Guide says to 2; 8 is needed for this liquid)*
- `8` → `60` mmol in steps of 1

…and the mirror image on the negative (acid) side.

Why 8: the bicarbonate's two equivalence points sit at −5 and +5 mmol, where the curve bends
sharply. With 1 mmol steps there, the lookup is up to 0.47 pH off between points (0.07 pH
at pH 6.0, the INT-S2 band edge). With 0.05 mmol steps out to 8 mmol it is under 0.005 pH
everywhere.

### Example

```csv
case,temp_c,excess_mmol,ph
T1,25.0,-60.000,1.959
T1,25.0,-59.000,1.967
...
T1,25.0,-5.000,4.679
...
T1,25.0,-0.002,8.289
T2,25.0,0.000,8.297
T2,25.0,0.002,8.305
...
T2,25.0,60.000,12.042
```

## What is in this folder right now

`placeholder_nahco3_ph_table.csv` — **not Aspen output.** The tank liquid (5.000 L water +
0.420 g NaHCO3) as a closed carbonate system with pKa1 6.35 and pKa2 10.33, generated by
`python -m sim.make_placeholder_table`, so that the rest of the ISE work can be built and
tested before the Aspen tables arrive. It has the identical format, so replacing it is a
drop-in swap. Its `case` column reads `PLACEHOLDER-NaHCO3-acid` / `-base`.

`_placeholder_pure_water_ph_table.csv` — the earlier pure-water table from the report's
charge balance (Section 1.3, eq. 1.1–1.3). The leading `_` keeps the loader from reading it:
two liquids at the same temperature would be merged into one nonsense curve. Only the
pure-water known-answer tests load it, on purpose.

The loader prints a warning on every run while a placeholder is the only table present, and
`sim.chemistry.table_provenance()` returns `"PLACEHOLDER"` instead of `"ASPEN"`. Every CSV the
batch runner writes carries that word in a `chem_source` column, so no result can be mistaken
for an Aspen-backed one.

## When the real tables arrive

1. Copy the Aspen CSVs into this folder.
2. Delete `placeholder_nahco3_ph_table.csv` (or leave it — files with `placeholder` in the
   name are ignored as soon as any other table is present). Only put tables for the tank
   liquid here; anything else goes in with a leading `_`.
3. Re-run `python -m sim.batch --events 600 --seed 261 --out ISE-AT-01_batch.csv`.
   Nothing else changes.
4. `python -m sim.tests.test_known_answers` should still pass (the tank-liquid checks are
   hand calculations for the NaHCO3 liquid, within 0.05 pH). If it does not, tell Hattan
   before anyone quotes a number.
