# Aspen pH tables — file format (CHE → ISE)

**Owner of the format:** Hattan (ISE). **Owner of the data:** Abdulkarim (CHE).
This is the only thing the simulator needs from Aspen. Drop the files in this folder
and the simulator picks them up — no code changes.

## The contract

One CSV file per Aspen sensitivity run, **or** one combined CSV. Either works.
The loader concatenates every `*.csv` in this folder except files starting with `_`.

### Columns — exactly these four names, in any order, lower case

| Column | Units | Meaning |
|---|---|---|
| `case` | text | Which Aspen run this row came from: `T1`…`T6`. Free text, never parsed. |
| `temp_c` | °C | Temperature of the run (20, 25, 30, 35). |
| `excess_mmol` | mmol | Net strong-base excess in a **5.000 L** tank. **Negative = extra acid, positive = extra base.** |
| `ph` | — | Aspen's `PH` for the tank outlet stream at that excess. |

### Sign convention — please read this twice

`excess_mmol` is **base-positive**:

- Table T1 (adding 0.5 M HCl to water) produces rows from `0` down to `−60`.
- Table T2 (adding 0.5 M NaOH to water) produces rows from `0` up to `+60`.
- pH must therefore **increase** as `excess_mmol` increases. The loader checks this and
  refuses the file if it does not — that check is there to catch a flipped sign.

### Basis

Every row is for a **5.000 L** tank. The simulator corrects for the extra volume added by
doses itself, by looking the table up at `excess_mmol × 5.0 / volume_L`. Do not pre-correct.

### Point spacing

pH moves very fast near neutral: in 5 L, pH 6 → 8 is about 0.01 mmol. Use the spacing from
the Simulation and Dataset Guide (Part 1, A3):

- `0` → `0.2` mmol in steps of **0.002**
- `0.2` → `2` mmol in steps of 0.05
- `2` → `60` mmol in steps of 1

…and the mirror image on the negative (acid) side.

### Example

```csv
case,temp_c,excess_mmol,ph
T1,25.0,-60.000,1.921
T1,25.0,-59.000,1.928
...
T1,25.0,-0.002,6.398
T2,25.0,0.000,7.000
T2,25.0,0.002,7.602
...
T2,25.0,60.000,12.079
```

## What is in this folder right now

`placeholder_ph_table.csv` — **not Aspen output.** Generated by
`python -m sim.make_placeholder_table` from the charge-balance equations of the report
(Section 1.3, eq. 1.1–1.3) so that the rest of the ISE work can be built and tested before
the Aspen tables arrive. It has the identical format, so replacing it is a drop-in swap.

The loader prints a warning on every run while the placeholder is the only table present, and
`sim.chemistry.table_provenance()` returns `"PLACEHOLDER"` instead of `"ASPEN"`. Every CSV the
batch runner writes carries that word in a `chem_source` column, so no result can be mistaken
for an Aspen-backed one.

## When the real tables arrive

1. Copy the Aspen CSVs into this folder.
2. Delete `placeholder_ph_table.csv` (or leave it — files named with a `placeholder` prefix are
   ignored as soon as any other table is present).
3. Re-run `python -m sim.batch --events 600 --seed 261 --out ISE-AT-01_batch.csv`.
   Nothing else changes.
4. `python -m sim.tests.test_known_answers` should still pass. If it does not, tell Hattan
   before anyone quotes a number.
